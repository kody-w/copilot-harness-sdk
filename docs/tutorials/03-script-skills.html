Skills with scripts: what the harness sandbox will and will not run

A SKILL.md often ships code beside it: a scripts/run.py, a scripts/check.py. An InlineAgentSkill carries only the SKILL.md text, so this rung asks the published agent to run two such skills and records exactly what happens. The answer is more useful than a yes or no.

What goes in

SkillWhere its code livesWhat the agent can reach
hello-worldinline in the SKILL.md (the agent.py and a launcher, in fenced code blocks), with a three-step fallback: run scripts/run.py if present, else save the blocks and run them, else read the code and do what perform doeseverything: the code is text in the skill
brainstem-doctorscripts/check.py beside the SKILL.md, not inlinedthe SKILL.md only; the script never shipped

Build and deploy

a.perform(name="Brainstem Script Skills",
          description="... When a skill wants to run a script, try; if the sandbox refuses or the script is not "
                      "present, say exactly that in one sentence, then do what the skill's own fallback says. "
                      "Never claim a script ran when it did not.",
          skills=["hello-world", "brainstem-doctor"], deploy=True,
          environment="https://<org>.crm.dynamics.com/", tenant="<tenant>")

Plain deploy, no profiles: two behaviors and the settings file.

The findings

  • The harness has a sandbox, and it runs Python. Given code inline in the SKILL.md, the agent wrote the two blocks to files and executed them. On rung 2 the same skill hit "sandbox restrictions" on one run and fell back to reading the code; both runs produced the exact greeting because the SKILL.md carries its own fallback ladder. Write skills that way.
  • Script files beside a SKILL.md do not ship. An InlineAgentSkill is text. brainstem-doctor's scripts/check.py is simply absent in Copilot Studio, and the agent says so instead of pretending. To ship a script: inline it in the SKILL.md (as hello-world does), or turn it into a tool (an agent flow or connector, the rung 1 pattern).
  • The sandbox has its own skills. The doctor's scan found /app/skills/ with ten built-in analyzing-* skills, each with a preprocess.py. Those are the harness's, not yours; they show up in "what skills do you have" answers next to the ones you deployed.
